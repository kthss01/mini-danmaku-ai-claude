# Claude 주도 · Codex 보조 진행 가이드

## 현재 작업
[이슈 #2: 웹 전환](https://github.com/kthss01/mini-danmaku-ai-claude/issues/2)와 [상세 계획](WEB_PORT_PLAN.md)을 따른다. 웹 실행 절차는 [WEB_SETUP.md](WEB_SETUP.md)에 있다. AI 구현은 웹 완료 이후다.

## 역할과 작업 단위
Claude: 조사·구현·실행 검증·문서·PR 생성·머지.
Codex: PR diff·재현 절차·실행 증거 검토 및 문제 정리.
사용자: 실제 화면 확인과 방향 결정.

모든 작업은 브랜치 → 커밋·push → PR → 검증·리뷰·수정 → 머지까지 진행한다. main 직접 push와 강제 push는 하지 않는다. 같은 파일을 동시에 수정하지 않는다.

## 여러 Claude 세션으로 나눠 진행할 때
웹 전환은 5개 세션(빌드·런타임·셸·서버·통합 QA)으로 나눠 진행했다. 분할과 결과는 [WEB_PORT_PLAN.md](WEB_PORT_PLAN.md)의 "운영" 절에 있다. 같은 방식을 다시 쓸 때의 규칙:

- 세션마다 별도 clone(또는 submodule까지 격리한 worktree)과 담당 브랜치를 쓴다. 빌드 출력·서버 포트·브라우저 탭을 공유하지 않는다.
- 담당 파일 밖은 수정하지 않는다. 다른 세션 파일의 결함은 그 세션 이슈에 재현 절차와 함께 전달한다.
- 산출물 경로·파일 이름·런타임 요구처럼 다른 세션이 의존하는 계약은 구현 초기에 이슈 댓글로 공유한다.
- fork 수정은 런타임 담당이 fork PR로 머지하고, 메인 submodule 참조 갱신은 빌드 담당 한 세션만 한다.
- README와 통합 문서는 통합 QA 담당이 소유한다.
- 로컬 서버를 띄우기 전에 포트가 비었는지 확인한다. 다른 세션이 같은 포트를 쓰면 잘못된 산출물을 검증하게 된다.

## 브라우저를 통한 보고
Claude는 검토 창구인 브라우저의 Codex 대화에 PR URL, head SHA, 검증 명령·결과, 실제 플레이 범위, 알려진 제약을 남긴다. Codex가 검토 결과를 이 대화와 PR 댓글로 전달하면 Claude가 수정한다. 이 대화를 도구 간 자동 통신 채널로 가정하지 말고 실제 보이는 보고를 기준으로 작업한다.

- **상세 보고와 검토는 GitHub PR·이슈 댓글이 우선**이다. 이 대화에는 PR·이슈 링크와 짧은 요약만 남긴다.
- 세션마다 그 대화를 연 전용 탭을 하나씩 쓴다. 다른 세션의 탭은 옮기거나 닫거나 입력하지 않는다. 별도 대화를 만들지 않는다.
- 전용 탭이어도 **같은 대화의 입력창 초안은 모든 탭이 공유**한다. 다른 세션이 쓰던 초안을 고치거나 지우거나 대신 보내지 않는다. 입력창에 남의 초안이 있으면 그 세션이 보낼 때까지 기다린다.
- 보고 첫 줄은 `[세션 N / 이슈 #번호]`, 다음 줄에 현재 적용된 모델·노력치를 적는다.
- 보고 전에 GitHub 기록과 대화를 확인해 자기 보고에 대한 최신 지시를 본다. 지시를 확인하면 사용자에게 다시 묻지 않고 진행한다.
- 보낸 뒤에는 실제로 한 번 게시됐는지 확인한다. 화면에 안 보인다고 바로 다시 보내거나 새로고침을 반복하지 않는다. 긴 대화는 일부만 로드되거나 "불러올 수 없습니다"가 뜰 수 있으므로, GitHub에 남긴 기록과 전송 여부를 먼저 대조한다. 실제로 유실된 것이 확인될 때만 다시 보낸다.

## 사용 한도와 모델
- 보고에는 현재 적용된 모델·노력치를 그대로 적는다. 세션은 자기 모델·노력치를 바꿀 수 없다.
- 보고에 사용 한도를 적을 때는 앱이 보여 주는 값이 사용률인지 밝히고, 초기화 날짜·시각·시간대를 함께 적는다. 컨텍스트 사용량과 사용 한도는 구분한다.
- 단기 한도가 임박하면 담당 이슈에 체크포인트(상태·작업 위치·재개 후 할 일)를 남긴다. 추가 유료 크레딧은 켜지 않는다.
- 재개 예약은 환경이 지원할 때만 시도한다. 보고에는 **예약 등록, 예약 실행, 실제 세션 재개를 구분**해 적고 자동 재개를 보장하지 않는다.
- 실제 사례(2026-10-24): 세션 5의 예약 작업이 정시에 실행돼 "성공"으로 기록됐지만, 아무도 열지 않은 예약 실행이라 다른 세션에 메시지를 보내는 도구가 사람 승인을 요구해 두 번 모두 실패했다. 세션 5는 사용자가 직접 메시지를 보낸 뒤에야 재개됐다. 따라서 체크포인트만으로도 사람이나 다음 세션이 이어갈 수 있게 남긴다.

## 머지
보호 규칙과 필수 검사를 충족하고 리뷰에서 발견한 차단 문제가 해결되면 별도 재확인 없이 검증한 head를 머지한다. 필요한 외부 승인 등 차단이 있으면 우회하지 않고 보고한다. 자신의 PR에 허위 승인을 기록하지 않는다.
Taisei fork 수정은 fork PR을 먼저 머지한 후 메인 submodule 참조를 갱신한다. 실제 통합 검증 전에 이슈가 자동으로 닫히지 않도록 부분 PR에는 `Closes` 대신 `Refs`를 쓴다.

## 검증
빌드 성공·초기 화면·실제 플레이를 구분한다. 실패·미검증을 성공으로 표시하지 않는다. 성공 기준을 일부만 확인한 항목은 미검증으로 두고 확인한 부분과 남은 부분을 적는다. 검증 기록에는 커밋 SHA뿐 아니라 작업 트리 상태와 산출물 출처(빌드 시각·해시)를 남기고, 기존 산출물로 한 탐색 검증과 새 checkout 공식 검증을 구분한다. 실시간 조작에 매 프레임 LLM 호출을 사용하지 않는다.
