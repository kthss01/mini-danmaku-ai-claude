## 1. 기술적 제약과 기존 계획과의 관계

1. **리소스 파이프라인**: 스프라이트는 `game/taisei/atlas/` 원본을 아틀라스(`gfx/common.tsatlas.zst`, `gfx/portraits.tsatlas.zst`)로 다시 묶어야 반영된다. 웹 빌드 컨테이너는 아틀라스를 재생성하지 않으므로 재생성 결과를 fork에 커밋한다. 도구(`scripts/gen-atlas.py`, pip: Pillow·rectpack·numpy·backports.zstd)는 UI 현대화 작업에서 이미 검증했다(portraits 106초). **모든 아틀라스 스프라이트는 원본의 0.5배로 표시**된다(`scripts/taiseilib/atlas.py`의 `DEFAULT_SPRITE_SCALE = 0.5`). 즉 원본은 표시 크기의 2배 해상도로 만든다.
2. **웹 빌드 경로**: fork 커밋 → `scripts/build-web.ps1`(Docker, 약 6분) → 로컬 확인 → fork PR 머지 → 메인 `game/taisei` gitlink 갱신 PR → main 머지 → GitHub Pages 자동 배포. 셰이더를 새로 넣을 일은 없다(넣으면 `shader/meson.build` 목록 등록이 필요하다).
3. **규칙 보존**: 보스 피격 판정은 스프라이트와 무관한 고정 반지름(`src/boss.h` `BOSS_HURT_RADIUS 16`)이고, 탄 판정·패턴은 `src/stages/stage1/spells`, `nonspells` 코드에 있다. 그림·애니메이션·색·문자열만 바꾸면 리플레이(입력·시드 기록)와 AI 기준선(#19)에 영향이 없다. 단, 코드가 호출하는 애니메이션 이름 `main`, `(9)`는 새 `.ani`에도 있어야 한다.
4. **다국어**: #37/#38로 한국어가 추가되어 번역 원본이 fork `po/ko.po`다. 새 이름·칭호·대사는 영어 msgid를 바꾸는 것이므로 `ko.po`에도 짝을 넣어야 한국어 UI에서 영어로 남지 않는다. 한글 글꼴은 기존 CJK 대체(`*_cjk.font`)로 충분하다([docs/web/L10N.md](../web/L10N.md)).
5. **동시 작업**: fork에서 AI 브리지(PR #39, `feat/ai-bridge`)와 UI 현대화(`feat/ui-modern-menus`)가 진행 중이다. 테마 작업이 만지는 파일(`src/stages/stage1/cirno.c`, `src/dialog/*`, `src/menu/charprofile.c`, `atlas/`, `gfx/`)은 둘과 겹치지 않지만, gitlink 갱신은 한 번에 하나씩 순서를 정해야 한다. #31(탄막 시각 표현)은 AI 기준선 이후 과제이고 이 테마 작업은 그와 별개의 "캐릭터·텍스트 교체"이므로 **별도 이슈로 추적**하는 것이 맞다.
6. **이미지 생성의 한계**: 생성형 도구는 프레임 사이·표정 사이의 일관성이 약하다. 그래서 "같은 캔버스·같은 포즈" 세트를 받고, 표정 패치 잘라내기·호흡 프레임 보간·여백 정렬은 이쪽에서 스크립트로 처리하는 분업이 현실적이다(4·5절).
7. **출처 표기**: 새 그림의 제작 도구·제작자·사용 조건을 fork `COPYING.txt`에 적는다(현재 초상화 afensorm CC BY 4.0 문단 아래). 동방 캐릭터를 자체 캐릭터로 바꾸는 것은 팬게임 2차 창작 부담을 줄이는 방향이다(나머지 보스는 그대로).

### 캐릭터: MINIVELO 추천

- 작은 보스 역할과 성격이 맞는다. 현재 대사가 "허세 부리다 지고 투덜대는" 구조라 발랄한 장난꾸러기 톤으로 다시 쓰기 쉽다.
- 탄막 콘셉트 "작은 고리와 펼쳐지는 부채꼴"이 Cirno의 기존 패턴(부채꼴 고드름 Icicle Cascade, 고리형 Snow Halation, 흩뿌림 Perfect Freeze)과 형태가 닮아 1차에서 패턴을 바꾸지 않아도 어색하지 않다.
- 74×110px 표시 크기에서도 민트 양갈래 + 케이프 + 반바지 실루엣이 구별된다.
- 대안 CLIMBER: 흰색·연보라가 얼음 탄과 가장 가깝지만, 차분한 성격은 스테이지 1 대사 구조와 거리가 있어 대사를 더 많이 고쳐야 한다.

다른 4명의 배치는 아직 정하지 않는다. 참고용 후보만 적어 두면 AERO ↔ 스테이지 5 Iku(빠른 직선·번개), CLASSIC ↔ 스테이지 4 Kurumi(우아함·대칭), RANDONNEUR ↔ 스테이지 3 Wriggle(반딧불·궤적), CLIMBER ↔ 스테이지 2 Hina(산·회전) 정도이며, 각 보스의 애니메이션 세트는 Cirno보다 크다(5절 표).

## 4. 이미지 요구사항 — 실제 규격과 제작 권장 규격

표시 배율이 0.5이므로 "표시 px"는 게임 화면(800×600 창, 플레이 영역 480×560) 기준이고 원본은 그 2배다. 모든 그림은 **투명 배경, 알파 경계가 깨끗한 PNG(또는 무손실 WebP)** 로 받는다. 아틀라스 패커가 투명 여백을 자동으로 잘라내되 여백만큼 위치를 보정하므로, 여백 크기 자체보다 **같은 세트 안에서 캔버스 크기와 캐릭터 위치가 모든 장에서 같아야** 기준점이 흔들리지 않는다.

### 4.1 전투 스프라이트 (보스)

| | 실제 규격 (Cirno) | 새 그림 권장 규격 |
| --- | --- | --- |
| 캔버스 | 148×220 px, 12장 모두 동일 | **160×240 px**, 12장 동일(2행×6열 시트 960×480도 가능) |
| 표시 크기 | 74×110 표시 px | 80×120 표시 px(비슷한 존재감 유지, 더 크면 탄을 가린다) |
| 기준점 | 캔버스 중심 = 보스 좌표. 모든 프레임에서 수평 중심 74px, 발끝 y 194~203px | 수평 중심 = 캔버스 중심, 발끝 = 캔버스 아래에서 12px 위, 머리 위 여백 8~16px. 캐릭터 높이는 캔버스의 85% 이상 |
| 방향 | 정면~약간 3/4, 좌우 반전 없음(보스는 플레이어처럼 좌우 스프라이트가 없다) | 같음. 좌우 비대칭 장식은 한쪽으로 통일 |
| 상하 흔들림 | 코드가 ±6 표시 px 사인파로 띄운다(`boss_get_sprite_offset`) | 대기 프레임에 큰 상하 이동을 넣지 않는다 |
| 글로우·그림자 | 스펠 중 현재 프레임의 실루엣을 `glowcolor`로 띄우고, 평소엔 `shadowcolor` 연기 입자 | 실루엣이 글로우가 되므로 외곽이 뚜렷해야 한다 |
| 표현 | 평면 채색, 외곽선 가늘게 | 3~4톤 평면 채색, 1px 디테일 금지(0.5배에서 사라짐), 헤어·대표색·의상 실루엣으로 구별, 자전거 본체 없음(작은 장식만) |

| 스펠 배경 | `stage1/cirnobg`(basis) 두 층을 서로 다른 속도로 스크롤하고 한 층은 곱하기(`BLEND_MOD`) 블렌드, 위에 `stage1/snowlayer` 눈 | 1024×1024 **이음새 없는 타일**, 중간 대비·중간 명도(곱하기 층으로도 쓰임), 민트·크림의 클로버·티켓·작은 고리 무늬. png/webp로 넣으면 `.basis` 없이도 로드된다 |
| 글로우·그림자 | `glowcolor = RGB(0.2, 0.35, 0.5)`, `shadowcolor = RGBA_MUL_ALPHA(0.6, 0.7, 1.0, 0.25)` | 팔레트에서 글로우(진한 민트, 예 `RGB(0.25, 0.65, 0.55)`)·그림자(연한 민트, 예 `RGBA_MUL_ALPHA(0.7, 0.95, 0.85, 0.25)`) 선택. HEX 5색 팔레트를 받으면 정한다 |
| 탄 색 | 스펠·논스펠 코드가 지정(얼음 파랑·흰색) | 1차 유지. 규칙이 아니므로 2차에서 팔레트 색으로 바꿀 수 있다 |

## 5. 전투 애니메이션 규격

`.ani` 파일 형식: `@sprite_count = N`, `이름 = [m] d<지연 프레임> 인덱스…`(`m`은 좌우 반전, `d5`는 각 프레임을 5게임프레임 = 1/12초 유지). 코드는 이름으로 재생을 요청한다.

| 보스 | 시퀀스(프레임 수) | 비고 |
| --- | --- | --- |
| **Cirno** | `main` 대기 6, `(9)` 공격 6 | 중간보스·보스 공용, 반전 없음 |
| Hina | `main` 6, `guruguru` 회전 5 | |
| Wriggle | `main` 6, 비행·특수샷 등 5개(18장) | 중간보스 전용 시퀀스 있음 |
| Kurumi | `main` 6, `muda` 6 | |
| Iku | `main` 6(+반전), 돌진·차지 6(좌우 반전 변형) | 유일하게 좌우 방향 있음 |
| Elly | `main` 6, 가위·박수 12장 | |

Cirno 교체에 필요한 것:

- `main`(대기): 6프레임 루프, 코드가 상하 부유를 더하므로 머리카락·케이프·양갈래가 살짝 흔들리는 정도. 스테이지 1 공격 코드(`nonspells/*.c`, `spells/crystal_rain.c` 등)가 `(9)`를 3루프 또는 스펠 내내 재생하고 `main`으로 돌아온다.
- `(9)`(공격): 6프레임 루프. 손을 뻗거나 뛰어오르는 "공격 자세" 하나를 잡고 그 안에서 작게 움직이는 루프.
- 프레임 수를 바꾸려면 `.ani`의 `@sprite_count`와 인덱스만 고친다. 지연 `d5`로 6프레임이면 한 루프 0.5초.

제작 현실에 맞춘 두 가지 수령 방식:

1. **시트 방식(권장)**: 960×480 PNG 한 장, 2행×6열, 셀 160×240, 1행 대기 6장·2행 공격 6장, 셀마다 캐릭터 위치 동일.
2. **키포즈 방식(대안)**: 대기 1장 + 공격 1장(각 320×480, 2배)만 받고, 호흡·흔들림 프레임은 이쪽에서 작은 변형(1~2px 상하, 0.5~1% 가로 신축, 케이프 레이어 흔들림)으로 6장씩 만든다. 시트의 프레임 간 일관성이 나쁘면 이 방식이 더 깔끔하다.

## 6. 이미지 수령 후 적용·검증 순서

1. **규격 검사**(스크립트): 캔버스 크기 일치, 알파 채널 존재, 시트 격자 분할, 프레임별 실루엣 중심·발끝 위치 편차(±2px), 초상화 3장의 몸 실루엣 일치(표정만 달라야 함). 결과를 표로 남기고 어긋나면 재요청 항목을 적는다.
2. **파일 배치**: `atlas/common/boss/cirno.frameXXXX.png`, `atlas/portraits/dialog/cirno.webp`·`cirno_variant_defeated.webp`로 복사, 표정 패치를 잘라 `cirno_face_{normal,angry,defeated}.webp` 생성, `atlas/config/dialog/cirno_face_*.spr` padding 계산, `gfx/boss/cirno.ani` 프레임 수 확인, 스펠 배경 타일을 `gfx/stage1/`에 추가.
3. **아틀라스 재생성**: `gen-atlas.py`로 `common`(thorough 프리셋)과 `portraits` 재생성 → 산출물 커밋.
4. **코드·문자열**: 3절 표대로 이름·칭호·대사·색·배경 참조 수정, `po/ko.po`에 한국어 짝 추가(말투 표는 [L10N.md](../web/L10N.md) 3장에 맞춰 새 화자 행 추가), `COPYING.txt` 출처.
5. **빌드·확인**: 웹 빌드 → Stage Practice 1(Easy)에서 중간보스 등장·대기/공격 애니메이션·스펠 컷인·보스 전 대화(3캐릭터)·패배 대화·변형 초상화 → 미디어룸 캐릭터 프로필 → 옵션 한국어 전환 후 같은 화면. 전/후 스크린샷을 `docs/design/screenshots/`에 저장.
6. **규칙 보존 확인**: `git diff`에 `spells/`, `nonspells/`, `timeline.c`의 로직 변경이 없음을 확인하고, 기존 리플레이 1개를 변경 전후 빌드에서 재생해 결과(점수·클리어)가 같은지 본다.
7. **전달**: fork PR → 검토·머지 → 메인 gitlink PR(이 문서 갱신 포함) → main → Pages.

## 7. 다른 보스로 확장할 때 달라지는 점

- 스프라이트 세트가 커진다(5절 표). 특히 Iku는 좌우 반전 시퀀스, Wriggle은 중간보스 전용 시퀀스가 있다.
- 플레이어 캐릭터로 쓰려면 전투 스프라이트에 좌우 기울기 세트(`left`/`right`/전환 프레임, 11~12장)와 봄 배경·샷 그래픽이 추가로 필요하고, 샷 타입·대사·캐릭터 선택 화면까지 범위가 넓어진다. 보스 시험이 끝난 뒤 따로 검토한다.

## 8. 미결 사항

- 캐릭터 정식 이름(영어 msgid, 한국어 번역)과 칭호. 임시로 `MINIVELO`를 쓰면 대사·프로필에도 그대로 들어간다.
- 스펠 이름 5개를 테마에 맞게 바꿀지(규칙과 무관, 번역 5줄 추가).
- 탄 색을 1차에서 바꿀지(권장: 2차).
- 추적 이슈 생성 여부와 번호(이 문서와 PR이 참조할 대상).

## 9. ChatGPT 제작 요청서 (복사용)

아래를 그대로 전달하면 된다. 스타일 기준은 이미 받은 MINIVELO 콘셉트 시트다.

```text
[공통] 투명 배경 PNG, 알파 경계 깨끗하게, 배경·그림자·바닥 없음. 첨부한 MINIVELO 콘셉트 시트의 얼굴·헤어(민트 짧은 양갈래)·의상(크림 셔츠, 민트 케이프, 남색 반바지, 갈색 부츠)을 그대로 유지. 자전거 본체는 그리지 않고 케이프 자수·가방 장식 정도만.

1. 전투 스프라이트 시트 1장: 960×480px, 2행×6열(셀 160×240px). 1행 = 공중에 떠 있는 대기 동작 6프레임(머리카락·케이프만 살짝 흔들림), 2행 = 손을 뻗어 탄을 뿌리는 공격 동작 6프레임. 모든 셀에서 캐릭터 발끝은 셀 아래에서 12px 위, 수평 중앙, 키는 셀 높이의 85% 이상. 정면에서 약간 3/4 시점, 모든 프레임 같은 방향. 3~4톤 평면 채색, 굵은 실루엣, 1px 세부 묘사 없음(게임에서 절반 크기로 표시됨).
   (시트가 어려우면 대신: 대기 포즈 1장 + 공격 포즈 1장, 각 320×480px, 위 규칙 동일)

2. 초상화 3장: 각 640×1000px, 같은 포즈·같은 위치·같은 의상으로 얼굴 표정만 다르게 — (a) 평소 미소, (b) 도발하며 살짝 화난 표정, (c) 풀 죽어 당황한 표정. 머리 위 여백 40~80px, 무릎 아래는 잘려도 됨. 정면에서 약간 3/4 시점, 왼쪽을 바라봄. 글자·로고 장식 없음(화면에서 좌우 반전되어 쓰임).

3. 패배 초상화 1장: 640×1000px, 2번과 같은 캐릭터가 지고 나서 주저앉거나 비틀거리는 포즈, 표정은 (c)와 같은 계열.

4. 스펠 배경 타일 1장: 1024×1024px, 상하좌우 이음새 없이 반복되는 무늬, 민트·크림 계열의 클로버·여행 티켓·작은 고리 모티프, 대비는 낮게(위에 탄이 많이 그려짐), 캐릭터 없음.

5. 색 팔레트: 위 그림에서 쓴 대표색 5개를 HEX로(민트 메인, 크림, 남색, 갈색, 강조색 1).
```

요청서에 캐릭터 이름을 넣고 싶으면 8절의 정식 이름을 먼저 정한다.
