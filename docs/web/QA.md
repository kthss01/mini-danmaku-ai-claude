# 웹 통합 QA 매트릭스 (세션 5)

담당 이슈: [#8](https://github.com/kthss01/mini-danmaku-ai-claude/issues/8) · 부모: [#2](https://github.com/kthss01/mini-danmaku-ai-claude/issues/2)
브랜치: `test/web-integration`

이 문서는 세션 1~4의 결과가 `main`에 통합된 뒤 **새 checkout에서** 수행할 검증 항목과 판정 기준을 정의한다.
실제 결과는 `tests/web-play/evidence/` 아래의 증거 기록에 남기고, 이 문서의 상태 열은 그 기록을 요약한다.

## 판정 규칙

- 상태 값은 `미검증` / `성공` / `실패` / `미지원` / `차단` 다섯 가지만 사용한다.
- 직접 실행해 증거(명령 출력, 스크린샷, 콘솔·네트워크 로그)를 남긴 항목만 `성공`으로 표시한다.
- 성공 기준을 일부만 확인한 항목은 `미검증`으로 두고, 확인한 하위 동작과 남은 동작을 증거 칸에 적는다. `성공(탐색)` 같은 별도 상태를 만들지 않는다. 탐색 여부는 기록 전체의 "검증 종류"로 구분한다.
- 빌드 성공, 제목 화면 표시만으로는 플레이 항목을 `성공`으로 표시하지 않는다.
- `미지원`은 원인과 범위를 기록하고, 완료 차단 여부(출시 차단/비차단)를 함께 판정한다.
- 결함은 아래 "결함 전달 경로"에 따라 담당 세션 이슈에 전달하고, 수정 머지 후 해당 항목을 재검증한다.
- 모든 검증은 검증한 **메인 커밋 SHA + `game/taisei` submodule 커밋 SHA** 조합과 함께 기록한다.
- 커밋 SHA만으로는 부족하다. 메인·submodule 작업 트리의 미커밋 변경 목록과, 실제로 서빙한 산출물의 출처(빌드 시각, 도구 버전, `taisei.html`/`taisei.js`/`taisei.wasm` SHA-256, manifest 유무)를 함께 기록한다. 출처를 확인할 수 없는 산출물은 `출처 미확인`으로 적고, 그 산출물로 수행한 결과는 새 checkout 재현(QA-01) 통과로 표시하지 않는다.
- 기존 로컬 빌드 결과를 이용한 탐색 QA는 허용하되 기록에 `탐색(기존 산출물)`로 구분하고, 공식 판정은 통합된 `main`의 새 checkout 빌드로만 한다.

## 참고: 고정 커밋의 웹 런타임 구조

검증 절차 설계에 사용한 `game/taisei` 소스 사실(설계 시 `5668c41b`, 공식 검증 시 `f59212b7` — 차이는 리소스 내려받기 실패 시 오류 중단뿐, [RUNTIME.md](RUNTIME.md) 4장). 동작 여부는 실제 검증으로 확인한다.

- 저장소: `src/vfs/setup_emscripten.c`가 `/persistent/storage`·`/persistent/cache`를 사용하고 `src/vfs/sync_emscripten.c`가 JS `SyncFS`로 IndexedDB와 동기화한다. 설정·리플레이·진행 데이터 persistence 검증(QA-40~42)은 이 경로를 전제로 한다.
- 리소스: `src/vfs/emscripten_fetch.c`가 HTTP fetch로 리소스를 받는다. 따라서 리소스 404는 네트워크 탭에서 바로 드러난다.
- 메인 루프: `src/eventloop/executor_emscripten.c`가 `emscripten_set_main_loop`를 사용한다. 탭 숨김 시 브라우저가 프레임 콜백을 제한하므로 QA-23에서 복귀 동작을 확인한다.
- 스레드: `misc/ci/emscripten-build.ini`는 SDL pthreads를 끈다. 세션 2가 다른 요구를 밝히지 않는 한 COOP/COEP 헤더 검증은 범위 밖이다.
- 업스트림 셸(`emscripten/shell.html` → `taisei.html`)은 WebGL 2 컨텍스트를 미리 만들고, `window.onresize`로 canvas 크기를 맞추며 F11/F12 키를 가로챈다.
